# ADR-001: 静的サイトのホスティングにCloudFront + S3を採用する

## ステータス

Accepted

## コンテキスト

個人ウェブサイト（月記）を公開するためのホスティング基盤を選定する必要がある。コンテンツは純粋な静的HTMLであり、サーバーサイドの処理は不要。以下の要件を満たす構成を求める。

- HTTPS配信
- カスタムドメイン（apex）対応
- 低コスト・低運用負荷
- コンテンツ配信の安定性

## 決定

CloudFront + S3 の構成を採用する。

- **S3**: 静的HTMLコンテンツの格納先。パブリックアクセスを全ブロックし、CloudFront経由のアクセスのみを許可する
- **CloudFront**: CDNとしてHTTPS終端・キャッシュ・エッジ配信を担う。Price Classは `PriceClass_200`（北米・欧州・アジア）を採用し、東京エッジからの配信を確保する
- **Route53**: apexドメインからCloudFrontへのAliasレコード（A/AAAA）を管理する
- **ACM**: CloudFront用TLS証明書をus-east-1リージョンに作成する（CloudFrontの仕様上必須）

## その他の選択肢にしなかった理由

- **Vercel / Netlify**: フルマネージドで手軽だが、無料枠に制限があり将来的にコストが増加する可能性がある。またインフラをAWSに統一できず運用が分散する
- **GitHub Pages**: 無料で手軽だが、プライベートリポジトリでの運用やカスタムドメインのHTTPS設定に制限がある。将来的な拡張性も低い
- **EC2 + Nginx**: 静的サイトに対してオーバースペック。常時起動コストが発生し、OSやミドルウェアの管理も必要になる

## 結果

**ポジティブ:**
- フルマネージドでサーバー管理が不要
- CloudFrontのエッジキャッシュにより低レイテンシで配信できる
- S3 + CloudFrontの組み合わせは個人サイト規模では非常に低コスト
- AWSのShield Standard（無料）が標準付帯し、L3/L4 DDoSから保護される

**ネガティブ:**
- ACM証明書のDNS検証など、初期構築時にリソース間の依存順序を考慮する必要がある
- WAFを導入しないため、L7レベルのコスト攻撃リスクは残る（Billing Alertで異常検知する）
