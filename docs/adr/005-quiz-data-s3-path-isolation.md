# ADR-005: クイズデータをS3の同一バケット内パスで管理する

## ステータス

Accepted

## コンテキスト

クイズ問題データ（24個のJSON）がGitHubパブリックリポジトリに含まれており、問題内容が公開状態にある。データをGitHub管理から外し、S3で管理する方針を採用するにあたり、以下の選択肢を検討した。

1. **既存バケットのパス分離**: 静的サイト用バケット（`yamamoto-shuma-my-website-prod`）の `data/questions/` プレフィックスにクイズJSONを格納
2. **専用バケット新設**: クイズデータ専用の新規S3バケットを作成
3. **プライベートGitリポジトリ**: quiz-dataを別プライベートリポジトリで管理し、CI/CDでS3にデプロイ

なお、既存バケットはすでにVersioning有効・CloudFront OAC設定済みである。

## 決定

**既存バケットのパス分離**（案1）を採用する。

- クイズJSONは `yamamoto-shuma-my-website-prod` バケットの `data/questions/` プレフィックスに格納する
- CloudFrontの既存設定でそのまま `/data/questions/*.json` が配信される
- CI/CDデプロイワークフロー（`aws s3 sync --delete`）には `--exclude "data/questions/*"` を追加し、デプロイによるデータ削除を防止する

## その他の選択肢にしなかった理由

- **専用バケット新設**: OAC追加・CloudFrontオリジン追加・Terraform増加が必要。インフラ複雑度の増加に対してメリットが薄い。アクセス制御の分離やライフサイクルの差別化など、別バケットが優位になる条件が今回は当てはまらない
- **プライベートGitリポジトリ**: Gitの差分・レビュー・履歴が活用できる点で優れているが、個人サイトのスケールではCI/CD構成の複雑化がオーバースペック。手動同期ワークフローで十分と判断した

## トレードオフ

- **S3でのJSON管理は一般的ではない**: 構造化テキスト（JSON）のバージョン管理にはGitが標準。S3 Versioningは履歴を保持できるが、コミットメッセージのような変更理由を記録できない。また、変更のdiff確認やレビューフローが使えない。この決定は「個人サイト・手動ワークフロー許容・CI/CD複雑化を避ける」という制約に基づくものであり、チーム開発や本番サービスでは推奨しない
- **CI/CDの `--exclude` 設定を忘れるとデプロイのたびにクイズデータが削除されるリスクがある**: S3 Versioningで復元は可能だが、spec・タスクに明記し認識を担保する
